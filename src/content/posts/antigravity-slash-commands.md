## 引言：别把“指挥中心”一直挂在 1 档开

刚打开 **Google Antigravity（俗称“反重力”）** 的时候，绝大多数人的肌肉记忆都是把它当成增强版聊天框：输入需求，按回车，祈祷它别把项目改炸。

但只要你在输入框里轻敲一下 **`/`**，你会看到一长串下拉菜单弹出来——有 `/plan`、`/grill-me`、`/goal`、`/boost`、`/teamwork`、`/browser`、`/generative_ui`、`/schedule`、`/automation`、`/learn`、`/compact`、`/plugin`、`/btw`，如果你在终端跑 `agy` CLI 或者装了不少插件，列表甚至会更长。

其实，按下 `/` 弹出来的不是什么“花哨快捷短语”，而是 **Antigravity 的驾驶舱换挡器**——决定 Agent 下一步用**哪种推理模式、哪条工作流、哪套隔离工具**去干活。同样一句话，直接回车跟先挂上 `/grill-me` 或 `/goal`，最终质量和额度消耗能差出好几倍。

这篇长文结合 Antigravity 官方最新文档与本地实际配置，**把按 `/` 后可能出现的所有选项一次讲透**：先拆总结构，再逐条讲清“每个到底干嘛、什么时候用、怎么写、有什么坑”，最后补上动态 Skills 机制与 CLI 终端专属命令。

## 一、先建立全局认知：按 `/` 后看到的选项分哪 3 层？

![Google Antigravity / 斜杠命令 6 大能力版图](/images/posts/antigravity-slash-command-map.webp)

很多人困惑“为什么网上截图里的 `/` 菜单跟我电脑里数量不一样？”原因很简单——Antigravity 的 `/` 自动补全菜单是 **三层叠加** 出来的：

1. **第一层：核心内置工作流命令**（App 桌面端 / 网页端 & CLI 核心能力，比如 `/plan`、`/grill-me`、`/goal`、`/boost`、`/teamwork`、`/browser`、`/generative_ui`、`/schedule`、`/learn`、`/compact`、`/plugin`、`/btw`）。
2. **第二层：你当前环境启用的动态 Skills / Plugins / 旧版 Workflows**（例如内置的 `automation` 技能会让 `/automation` 出现在菜单中；你装了自定义技能或插件后，对应的可触发命令也会挂进 `/` 联想列表中）。
3. **第三层：Antigravity CLI（`agy`）交互终端独占的 20+ 控制命令**（在命令行里没有鼠标侧边栏，因此切模型 `/model`、看 Diff `/diff`、查上下文 `/context`、分支对话 `/fork` 全都塞进了 `/` 菜单）。

下面我们先逐个吃透最核心的 **13 个主力命令**，每个都讲清「原理 + 适用场景 + 实战怎么敲 + 注意事项」。

## 二、核心斜杠命令逐个拆解（App 桌面端最常用）

### A. 规划与需求对齐组：先谋后动，最省返工

#### 1. `/plan` —— 先调研、出方案，你批完再动代码

- **它是干嘛的**：强制把 Agent 从“上来就改文件”的默认状态，切换进**只读规划模式（Plan Mode）**。它会按四步推进：**只读代码调研** → **必要时澄清提问** → **生成可审阅的 `Implementation Plan`（实施计划）产物** → **等你点审批或批注修正后才动手改代码**。
- **什么时候按它**：涉及 3 个以上文件的大改、跨模块接口重构、数据库迁移，或者改坏了回头收拾很麻烦的敏感逻辑。
- **实战写法**：
  ```text
  /plan 给现有后端接入基于 JWKS 缓存的 OIDC 鉴权校验，并补全单元测试
  ```
  甚至可以什么都不写，直接单独输入 `/plan` 发送，让它先摸排当前仓库现状并和你在面板里对齐思路。
- **别踩坑**：小修小补（比如改一行文案、修个拼写错误）别硬套 `/plan`，白白多走一轮规划回合反而慢。

#### 2. `/grill-me` —— 把你的模糊想法“烤问”成清晰设计

- **它是干嘛的**：名字很形象，就是让 Agent 反过来对你做**一对一结构化需求访谈**。它遵循两条铁律：**代码库里自己能翻出答案的问题绝不问你**；每次只抛 **1 个选择题** 并把**它的推荐选项排在第一位**（当然你也可以点 `Other` 自己写或点 `Skip` 跳过），一直追问到你们对所有边界条件达成共识。
- **什么时候按它**：你心里只有个大方向（“加个限流”、“重构一下配置中心”），很多细节其实自己还没拍板——如果直接丢普通指令，Agent 只能按它自己的猜测蒙着写，十有八九跟你想要的不一样。
- **实战写法**：
  ```text
  /grill-me 我想给书签 API 加上按用户分级的请求限流能力
  ```
- **高阶用法**：新版桌面端（v2.26+）在弹出选择题卡片时**不再锁死底部输入框**，你随时可以在下面继续排队补充指令；另外官方最推崇把 **`/plan /grill-me <任务>` 叠着用**——先面试敲死细节，再无缝落成可审核计划。

### B. 深度推理与自主跑通组：啃硬骨头专用

#### 3. `/goal` —— 禁止中途“偷懒早退”的全自动闭环

- **它是干嘛的**：普通对话模式下，Agent 只要觉得“我这一步做完得差不多了”就可能停下来等你发“继续”。开启 `/goal` 后，系统会进入 **目标模式（Goal Mode）**：**只要它试图在目标未达标前结束回合，系统就会自动拦截它的停止动作并要求它继续自查与修复**，没有最大轮数限制，直到它能**把你的每项交付要求逐条映射到真实文件/测试日志证据**（或你主动取消）才允许结束。输入框上方还会亮起 **Active Goal** 状态条提示你它正在长跑中。
- **什么时候按它**：批量修挂掉的单测、一轮大规模 Lint / 类型错误清零、脚本化迁移、或者你准备睡前/出门前交给它跑完的任务（“修到全绿才许停”）。
- **实战写法**：
  ```text
  /goal 修复 auth 包下面所有失败的单测并确保全量测试 100% 通过
  ```
- **核心提醒**：`/goal` 只改变“不到终点不准停”的行为，**并不会绕过你原本配置的安全权限与命令审批策略**；而且目标务必写得**具体可验证**（例如“构建零报错、测试全通过”），别写“帮我把项目优化得优雅一点”这种没法验死的虚词。

#### 4. `/boost` —— 付费档三层多智能体深度推理

- **它是干嘛的**：遇到单一模型一轮想不透的硬核难题时，`/boost` 会按需拉起一套 **三层多智能体推理流水线**（`Orchestrator` 统筹 → `DeepCoder` / `DeepInvestigator` 并行深挖多条假设并跑实验 → 独立验证轮次交叉核验结果），把高概率成立且实测站得住的方案交回来。
- **什么时候按它**：棘手的并发死锁与竞态 Condition、复杂算法性能压榨（比如 SIMD / 内存布局优化）、跨层玄学回归 Bug。
- **实战写法**：
  ```text
  /boost 排查并修复连接池在高并发重连场景下的偶发死锁问题，并补充压测复现用例
  ```
- **省钱防坑**：这是**付费订阅档专属高算力模式**，能用普通模型解决的日常接口或排版活千万别开 `/boost`，免得快速烧穿配额。

#### 5. `/teamwork`（完整官方名 `/teamwork-preview`）—— 跨天多智能体团队战役

- **它是干嘛的**：面向“单条会话上下文塞不下”的超大型工程与开放式研究（付费档可用）。一触发就先由 **Sentinel（哨兵协调官）** 跟你在聊区确认作用域、立项写规划，随后拉出 **Project Orchestrator（项目总管）**、研究与执行 Worker，以及带**对抗式验收门禁的 Success Auditor（成功审计官）**，拆成里程碑分波协同推进，并在隔离目录里跑测试验证。
- **它和 `/boost` 怎么分**：**`/boost` 像是请专家组现场会诊一个疑难杂症（分钟~小时级）**；而 **`/teamwork`（`/teamwork-preview`）是直接包一支研发+测试团队进驻跑整个项目/大迁移（小时~跨天级）**。
- **实战写法**：
  ```text
  /teamwork-preview 把后端 REST 服务从 Express 整体迁移到 Fastify，要求全套接口和单测 1:1 对齐
  ```

### C. 浏览器实操、可视化挂件与旁路工具组

#### 6. `/browser` —— 派出沙盒 Chrome 子代理去点页面、验收与排障

- **它是干嘛的**：显式唤醒内置的 **Sandboxed Browser Subagent**。它不是简单的 `curl` 抓源码，而是真的能打开页面、点按钮、填表单、切移动端视口、等待元素出现、**读取浏览器 Console 报错和 Network 请求状态**，并在结束时保存高清截图与整段 **WebM 操作录屏**到 Artifacts 里（可用界面：Antigravity App 与 CLI；Antigravity IDE 插件版无此子代理）。
- **什么时候按它**：前端样式调完要实际看渲染、查接口报没报跨域/404、做表单端到端回归测试，或者抓取需要 JS 渲染才能看见的网页内容。
- **实战写法**：
  ```text
  /browser 打开 http://localhost:4321/compass/ ，分别点选几个分类标签和搜索框，确认零报错后截图汇报
  ```
- **配合诀窍**：涉及账号登录、二次验证或反爬验证码时，自己在内置浏览器里过完人机验证再放手让 `/browser` 跑繁琐重复操作。

#### 7. `/generative_ui` —— 桌面端独占：用交互式网页替你把抽象逻辑演出来

- **它是干嘛的**：**仅 Antigravity App（桌面端/Web）可用**（CLI 纯文本终端不支持）。有些原理干写 500 字还不如一张可点击的小图——它让 Agent 当场生成一个**单文件自包含、支持你当前浅色/深色主题的交互式 HTML 挂件**。
  - **紧凑小组件**（如 500px 内的流程图/公式推演器）：直接嵌进对话回复里就能点！
  - **大型仪表盘/交互原型**（默认形态）：生成独立 Artifact，在右侧边栏全高铺开把玩。
- **什么时候按它**：想一眼看懂请求过中间件的链路、对照调整参数看曲线变化、整理复杂的架构对比表，或者现场让它捏个交互原型先看手感。
- **实战写法**：
  ```text
  /generative_ui 画一个展示中间件鉴权到数据库查询的数据流交互图，加上“Token 有效 / 过期”切换开关，放在对话内嵌视图里
  ```

#### 8. `/btw` —— 不打断、不胀气上下文的“顺手旁路问一句”

- **它是干嘛的**：想象你正让主 Agent 跑着 3 分钟的重型重构或测试，忽然想问一句“对了，你刚说那个配置结构体叫啥名来着？”。在主框正常发消息不仅可能排队阻塞，还会永久把一问一答塞进主对话上下文，后面每轮都要多付一遍 token 账单。
  `/btw`（by the way）会**按当前对话瞬时分出一条纯文本旁路线程（不带文件读写/终端工具）**，**哪怕主 Agent 正在流式输出也照样立刻作答**；而且问答完**不会写入主对话历史**，临时分支自动清理，零上下文膨胀！（在 CLI 里甚至还能用 `/copy btw` 一键把 `/btw` 的回答复制到剪贴板。）
- **实战写法**：
  ```text
  /btw 刚才修改的那个超时参数默认值是多少秒？
  ```

### D. 定时任务与后台自动化组（最易混淆的一对）

#### 9. `/schedule` vs `/automation` —— 同样是定时执行，底层完全不是一回事！

很多同学看到既有 `/schedule` 又有 `/automation`（如果你看见菜单里带 `/automation`，其实它触发的是内置的 Scheduled Automations 创建向导技能），很容易搞混。一张表直接分清：

| 对比维度 | `/schedule`（会话内定时器 / Cron） | `/automation`（独立后台自动化 Sidecar） |
| :--- | :--- | :--- |
| **生命周期** | 依附于**当前对话**；关掉或不再驻留就失效（除非专门配置为独立守护态） | **完全独立持久**，配置写入 `~/.gemini/config/sidecars/<id>/sidecar.json` |
| **触发方式** | 支持**一次性倒计时**（如“今天 10:56 / 15 分钟后”）也支持 Cron | 严格 **Cron 定时循环**，自动携带 `CRON_TZ=<IANA 时区>` |
| **执行上下文** | 直接**唤醒原对话继续接着干**，完整继承前面聊过的所有上下文和工作状态 | 每次触发都**新开一条干净会话**（`agentapi new-conversation`）跑预设的独立 Prompt |
| **典型场景** | “半小时后查一下发版流水线过了没”、“明早 11 点把我写完的草稿发出去” | “每个工作日早 9 点汇总未读 PR 并生成日报”、“每周一巡检依赖安全更新” |

- **`/schedule` 实战写法**：
  ```text
  /schedule 20分钟后 检查 GitHub Actions 部署结果，如果通过就把页面截个图给我看
  ```
- **`/automation` 实战提示**：敲完 `/automation`，Agent 会像填表向导一样一步步向你确认执行频率（每小时/每天/每周）、具体时间点和独立任务指令，并在 **Automations 面板** 里留给你总开关与最小权限配置，**不会越权擅自替你打开开机自启**。

### E. 记忆整理、上下文瘦身与生态扩展组

#### 10. `/compact` —— 聊太久上下文发虚时的“记忆浓缩器”

- **它是干嘛的**：对话跑了二三十轮后，哪怕模型窗口够大，塞满旧报错、废代码的上下文也会让推理注意力分散、响应变慢、额度激增。触发 `/compact` 后，Agent 会把前序已发生的讨论、结论与关键文件事实**压缩成一段高密度摘要**保留下来，甩掉冗长历史碎片，让这条线程轻装接着干。
- **什么时候按它**：发现 AI 开始反复忘掉早期的核心要求、或者一个任务阶段刚收官准备接着在同一窗口做下一阶段时。

#### 11. `/learn` —— 吃一堑长一智：把纠错沉淀成永久规则或技能

- **它是干嘛的**：AI 最头疼的问题是“新开一个对话就全忘了”——你花了二十分钟才教明白它“这个仓跑单测必须加 `--pool=forks`”，换个会话它又裸跑一遍报错。
  触发 `/learn` 后，Agent 会复盘你最近的修正对话（找哪里卡住了、最后怎么修通的），自动判断该存成**约束性 `Rule`**（每次必遵守的红线/规范）还是**步骤型 `Skill`**（可复用的排查剧本）；能更新旧文件的绝不瞎建新文件，而且**绝不偷改配置**——先写出 `learning_proposal.md` 提案给你审批，你点头它才真正写入 `~/.gemini/` 或项目 `.agents/` 目录。
- **实战写法**：
  ```text
  /learn 记住这个仓库验证前端必须直接用 biome.exe，不要跑 pnpm build 触发沙箱软链报错
  ```

#### 12. `/plugin`（CLI 别名 `/plugins`）—— 插件管理与能力市场入口

- **它是干嘛的**：用来安装、启用、禁用或把零散的 Rules / Skills / Subagents / MCP Server / Hooks 打包成可插拔的统一插件包。在 CLI 终端里输入 `/plugin` 可以直接呼出带 **Installed / Discover** 页签的插件市场界面，也支持命令行内联装卸；在 App 桌面端里可以直接输入 `/plugin 帮我查一下有哪些连 Google Docs 的插件` 让它检索 Marketplace 或帮你新建插件。

## 三、选型不迷路：一张决策图 + 4 套高阶组合技

![拿到任务按什么情境选 / 命令决策图](/images/posts/antigravity-slash-decision-tree.webp)

把单兵命令记住只是第一步，真正在一线省时省额度的秘密是**按任务节奏把几个 `/` 串起来打**：

1. **零返工新功能上线流**：`/grill-me`（追问把需求细节磨圆） → `/plan`（只读出改动计划并人工确认） → 执行编码 → `/browser`（实操验收页面与报错）。
2. **全自动修 Bug 进化闭环**：`/goal 修到全量测试 100% 通过` → 收工后顺手敲 `/learn`（把刚才怎么定位和躲开环境坑写进规则）。
3. **重度攻坚不堵车打法**：让 `/boost` 在主线跑深层推理，中途有任何小疑问直接敲 `/btw` 旁路秒查，主线与记忆两不耽误。
4. **临时定时 vs 固定早报**：像“写完稿子等明早 11 点定时发出”这种接续当前线程上下文的一次性定时任务，直接交给 **`/schedule`**；如果是“每天上午自动拉最新 PR 和待办”这种不依赖具体某段聊天的日常巡检，请出 **`/automation`**。

## 四、为什么我的 `/` 菜单多出一堆奇奇怪怪的词？——动态扩展机制

如果你装过社区插件、或者在项目 `.agents/` 里写过规范，按 `/` 时菜单里往往还会跟着出现诸如 `/conversation-forker`、`/local-desktop-ops`、`/migrate-workflows` 甚至团队自定义的流程名。这是因为 Antigravity 允许外部能力**热插拔进 `/` 菜单**：

- **Skills（技能包）**：放进项目 `.agents/skills/<name>/SKILL.md` 或全局插件里的 Skill，只要具备明确触发场景说明，就能以 `/skill-name` 形式直呼或被自动加载。
- **Plugins（插件捆绑）**：安装插件后，插件自带的所有对外暴露的 Skill 或命令入口会自动进入你的可用命令列表。
- **旧版 Workflows 迁移提示**：以前 Antigravity IDE 曾有 `.agents/workflows/*.md` 机制（直接靠 `/workflow-name` 跑多步宏脚本）。官方已公告旧版 Workflows 将于 **2026 年 10 月 19 日停止支持** 并全面转向 **Agent Skills** 体系——如果你仓库里还留着老的 workflow 文件，在框里直接敲 **`/migrate-workflows`**，内置向导会一键扫描并帮它们安全迁移成现代标准 Skills！

## 六、高频避坑 FAQ

1. **按 `/` 没反应，或者只想真的发一条以 `/` 开头的文本怎么办？**
   在输入文本时，只要开头不是直接键入触发菜单并选中命令，或者在 CLI 无头模式（`agy -p`）下配置 `--disable-slash-commands`（对应设置 `disableSlashCommands: true`），就可以强制把带 `/` 的话原封不动当普通文本传给模型。
2. **`/generative_ui` 和 `/browser` 为什么有时在某些端找不到？**
   因为端能力边界不同：`/generative_ui` 依赖图形界面渲染交互 HTML，**只在 Antigravity App（桌面端/Web）可用**；`/browser` 沙盒浏览器在 App 与 CLI 均可使用，但在 **Antigravity IDE 插件版内不可用**（且企业版管理员可能统一关闭浏览器权限）。
3. **用了 `/goal` 或 `/boost` 会跳过我的危险操作确认弹窗吗？**
   **不会。** 它们改变的是规划链路、并发验证方式和早退拦截策略，你的文件访问边界、沙盒模式、终端命令白名单 / 审批策略依然原封不动严格生效。
4. **`/plan` 和 `/grill-me` 每次都要两个一起开吗？**
   不是必须：需求已经很清澈但改造面广，直接 `/plan` 就行；想法还很毛坯拿不准产品/技术口径，先开 `/grill-me`；遇到又复杂又模糊的硬活，把 **`/plan /grill-me`** 连写在一起才是完全体。
